## Where the build differs from the plan's wording (none widens scope)

1. `with_deadline` returns what the worker recorded after it sets `CANCEL` and the worker returns. For a cancelled hang that is `TIMEOUT`, as planned. A call that ignored `CANCEL` would return its real result late; that is the open item owned by PAY-08.
2. `carrier.track` names only a tracking number, so the reconstruction also joins through the shipment outcome's tracking number. The plan named the intent join only.
3. The reference allow-list also holds the code-like outcome fields: `status`, `decision`, `reason`, `code`, `errorCategory`, `last_status`, `carrier`, `reasons`, and counts `score`, `scans`, `steps_ok`, `attempts`, `extra_args`.
4. Run-level failures: `model_unavailable` transient, `replay_miss` validation, `max_turns` business, `unexpected_error` unexpected, `audit_incomplete_run` transient (renamed from `audit_incomplete` after the re-review, N1). A run error with every step done gives `partial`, never `complete`.
5. `derive_status` with no required step gives `failed` (`test-writer`'s observation; zero of zero is not a success).
6. `tests/governance/test_tool_register.py` assumed `retrieve_context` was the only tool under `services/`. It now scans every file under `services/` for tool constants, and still requires a register row and the `@tool(` count for each. Its name capture is `[^"]+` again, as before the row (row review F6): the first version narrowed it to `[a-z_]+`, which was wider in files but narrower in names, not simply stricter.
7. The driver ships before it captures and voids on an undeliverable address (S5), so a held order is never charged.
