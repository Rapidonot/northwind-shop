## What this does

- **Parallel unit tests.** `pytest-xdist` 3.8.0 (and `execnet` 2.1.2) are in the root dev group.
  - `override PYTEST_PAR := -n auto --dist loadgroup` goes on the pytest line of `make test` and `make check`.
    `make ci` runs `test`.
  - CI's unit step is `uv run pytest -n auto --dist loadgroup`.
  - The flags go on the command line only, never in `addopts` or `PYTEST_ADDOPTS`. Nested pytest runs inside
    the tests inherit the environment, and `addopts` would reach `make record`.
  - Integration, e2e, `record`, `eval-live`, `enrich` and the eval targets stay serial.
- **CI once per PR push.** `ci.yml` runs on `pull_request` and on `push` to `main`. The removed run tested the
  bare branch head, a tree that never lands. The pull_request run tests the merge ref, which is what `ship`'s
  merge commit lands. `check_jobs` matches jobs by workflow and name, so each required job is still seen, now
  once instead of twice.
- **`python-integration`** is a new job beside `python`, with the same Postgres service and replay environment.
  It runs `uv run pytest -m integration`, still serially. `python` keeps lint, mypy, the scan and the unit tests.
  `tools/ship.sh` `REQUIRED_JOBS` gains `CI/python-integration`.
- **Timeouts** on every job: 2x the slowest measured job, rounded up to 5 min, with at least 10 for jobs that
  start Postgres or install a browser.
  - CI: python 35, python-integration 40, eval-gate 10, e2e 10, portal 5.
  - Guard: eval-gate-main 10, baseline-label 5, eval-integrity-main 5.

  The previous default was 360 min. A timeout is a failure, and `ship` refuses it.
- **Concurrency**, the key from #12's plan, in both workflows, with `cancel-in-progress: true`:
  `${{ github.workflow }}-${{ github.ref }}-${{ github.event.action == 'synchronize' && 'push' || github.run_id }}`.
  Only `synchronize` runs share a group, so a new push cancels the old SHA's run, which `ship` never reads. Label,
  edit, open and reopen runs, and the push to `main`, are never cancelled.
- **Ship ordering.** Once this ships and the runner syncs, `ship` refuses an open PR whose head has no
  `CI/python-integration` check ("job missing"). 12b has already shipped (#46). #16 merges main before its own
  ship, so its head runs the new `ci.yml`. Any other PR opened before this one needs main merged in, or a push.
