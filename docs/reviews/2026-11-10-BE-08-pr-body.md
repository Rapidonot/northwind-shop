## What this does

- **Every backend action writes an audit event (BE-08, partial).** `services/backend/src/northwind_backend/audit.py`.
  - Each port call through an audited view writes an `attempt` before it runs and one `outcome` after it. Both
    carry the actor, the action, inputs by reference, the outcome and the correlation ID.
  - **Inputs and outcomes are references.** Card data is refused first, in strings and in numbers' digits, with no
    digest. Allow-listed IDs and codes are written as they are. Anything else (a payment token, a postal code,
    model text, an unknown argument name) is written as type and length, or only counted. No message is written.
  - **Append-only and hash-chained.** `verify_chain` finds an edit, an inner delete, a reorder, an insert and an
    edited `event_id`. Two limits are stated and pinned: a truncated tail and a full recompute can't be found
    without an outside anchor, which NFR-10 owns.
  - **Fail closed.** If the attempt can't be written, the call never runs (`AUDIT_UNAVAILABLE`). If the outcome
    can't be written, the caller gets `AUDIT_INCOMPLETE`, and a same-key retry settles it with no second effect.
- **Any order can be rebuilt from events alone.** `reconstruct.py`.
  - All 1,000 synthetic orders are run through the audited views, written to JSONL and reloaded with the fakes out
    of reach. Each rebuilds to the fakes' ground truth: fraud, payment status and amounts, shipment, tracking, and
    the exception reached.
  - A money call that timed out after taking effect is listed as `uncertain`, with its amount. It is never reported
    as absent and never counted as done (R1). It is settled by any `Ok` under the same idempotency key, whatever
    the event order (S1), or by a status read after its last doubtful attempt. A dry run never settles it (row
    review F1, F2).
  - One comparison rule (`_reconcile.py::assert_reconciles`) checks every reconstruction test against the fakes'
    ground truth.
- **Structured errors and local recovery (BE-02, partial).** `errors.py` and `recovery.py`.
  - `AgentFailure` carries the failure type, the attempted action, partial results, fixed alternatives,
    `isRetryable` and the attempt count. `AgentResult` carries `complete`, `partial` or `failed`.
  - Transient failures are retried with the same call and the same key, up to `max_attempts`.
  - The deadline is real: the call runs in a worker thread. An injected hang waits before the effect and aborts
    with no effect when it's cancelled.
  - The status comes from the audited tool outcomes, never from the model's text. A valid empty result is
    `complete`. "Access failed" is `partial` or `failed`.
- **The first backend agent: the Orders subagent, read-only.** `agents/orders_check.py`, `agents/runtime.py`, on
  `ROUTINE_MODEL` (Haiku).
  - Two tools, `get_fraud_assessments` and `get_payment_status`, both inside the PRD §7 Orders row and both reads.
    Each is bound to the task's own IDs: any other ID is refused, audited, and never reaches the port.
  - The task's IDs are checked before they reach the prompt. The model sees no name, email, address, token or
    correlation ID.
  - Every tool use the model makes is audited, including calls to unknown tools.
  - **No agent or product code can reach `authorize`, `capture`, `void` or `refund`.** AST pins enforce this
    outside `fakes/` and `views.py`. The test-only order driver calls them on fakes, which the user accepted.
- **Per-caller views share one fake** (`views.py`), so the one-payment rule, the idempotency store and the refund
  cap hold across callers. This closes FOUND-3 open medium (1).
