## What this does

- **Planner** (`services/backend/src/northwind_backend/orchestrator/plan.py`)
  - Sonnet with one tool, `submit_plan`, and no data tools.
  - Code checks the plan before anything runs:
    - kinds are allow-listed (`payment_fraud`, `tracking`, `unsupported`), each with only its own fields;
    - IDs match their patterns and appear verbatim in the request;
    - every order and intent ID the request names is in some concern;
    - at most 4 concerns, with duplicates merged.
  - Every check, and the model, read one canonical text: NFKC with format characters removed, escaped inside
    `<request>` tags.
  - Card data, empty text and over-long text are refused before any model call. The length limit is checked on the
    raw text and on what the model reads.
- **Subagents, in parallel** (`orchestrator/run.py`)
  - `payment_fraud` runs #20's Orders subagent read-only slice, unchanged except for one fix: an intent that belongs to
    another order is refused (`intent_not_for_order`).
  - `tracking` runs the new Returns subagent's read-only tracking slice (`agents/returns_track.py`, one
    `track_shipment` tool through `AuditedCarrierPort(CARRIER_READ_ONLY)`, bound to the task's own parcel).
  - `unsupported` runs nothing and is annotated `not_supported`, with `escalate_to_care`.
  - All runs execute in one `asyncio.TaskGroup`, each under its own deadline. A deadline, a crash or a lost audit
    write costs only that concern's section.
  - A cancel from outside (Ctrl-C, a caller gone) closes every open attempt in the audit: the run and task levels in
    `orchestrator/run.py` (`_close_cancelled`), the subagent level in `agents/runtime.py`.
- **One result** (`orchestrator/aggregate.py`)
  - One status, built from the sections: complete, partial or failed.
  - One section per concern, carrying BE-02's failure type, attempted action, partial results and alternatives.
  - One correlation ID, `run-<hex>`; the children are `<run>.plan` and `<run>.tN`.
  - The answer is built from step values, never from model text (#20 C1).
  - A payment of another order is taken out of the section, values and all.
- **Audit (BE-08)**
  - `orchestrator.run`, `orchestrator.plan` and `orchestrator.task` events, with the subagent runs as children.
  - The request is written as its type and length only.
  - No run ID, time or deadline reaches a model. The same request twice gives identical request hashes per agent.
- **Demo:** `uv run python -m northwind_backend.orchestrator "<request>"` prints the one answer on fakes seeded from
  `data/backend/` (tracking and fraud flags; no payment). Model calls go through the proxy, so in replay only a request
