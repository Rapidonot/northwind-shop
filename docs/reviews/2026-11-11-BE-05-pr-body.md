BE-05 + CHK-05: the Orders agent places orders on the fakes, behind hard rule 9 on the payment port (row #21)

## What this does

- **Hard rule 9 on the payment port** (decision 0014; FOUND-3 open mediums 1 and 2):
  - **Confirmation reference.** `authorize` and `capture` require a `confirmation_ref` (`confirmations.py`). The rule
    is the user's:
    - authorize uses it up;
    - capture must present the reference that authorized the intent;
    - any other reference is refused, a fresh one for the same order included;
    - after a void, a new authorization needs a new confirmation.
  - **Who issues it.** Until CHK-02 builds the portal control, only a test fixture issues references. An AST pin
    keeps every `issue(` call out of `src`.
  - **Per-order limit.** `authorize` has a deterministic per-order limit per currency. The values are placeholders
    the user accepted: USD 2,000, CAD 2,700, GBP 1,600, EUR 2,100.
  - **Shared state.** The fakes' state moved to shared `PaymentState`, `FraudState` and `CarrierState`. The
    one-payment rule, idempotency, the refund cap, confirmation use and one assessment per order now hold across
    instances. Scopes stay per instance.
- **The Orders agent places an order** (`agents/orders_place.py`, Haiku via `ROUTINE_MODEL`, `agent_options()` only):
  - **Steps:** validate, fraud score, authorize, capture, confirm.
  - **Routine exceptions are resolved:** an undeliverable address is replaced by the shopper's address on file, and
    a soft decline gets one more authorization.
  - **Everything else is escalated** with context built by code from the run state, never from model text.
- **What decides, in code:**
  - Every tool takes only `order_id`. Any other order's ID is refused, audited and never reaches a port.
  - The amount, token and confirmation reference come from the order and the task, never the model.
  - Gates enforce the step order and at most two authorize attempts.
  - Every write key comes from the order ID alone, so a rerun presents the same keys.
  - **No second write after doubt.** After a timeout, an exception or `audit_incomplete`, `WRITE_POLICY` never calls
    a write again; the action is uncertain and the order is escalated. Each tool has its own model-facing error
    text (`agents/messages.py`; #20's C2).
  - **The store decides whether the order is open.** Before every write, the order is read again from the store.
    An order that another run escalated or placed gets no write from this run.
  - **The payment claim** (security review F1, the user's Option 1):
    - Before the payment call, the run takes a claim: a compare-and-set from `pending` to `paying`, owned by the
      run's code-only identity, outside the idempotency store.
    - A run that doesn't own the claim never authorizes. It escalates as `duplicate_in_progress`, and so does a
      rerun after a crash.
    - An escalation of a claimed order stores whichever view of the payment shows more money moved, so a hold or a
      capture is reported.
- **Least privilege.** The placement views hold exactly what the code calls:
  - payment `{authorize, capture}`;
  - fraud `{assess}`;
  - catalog `{price, stock}`;
  - orders `{get, use_address_on_file, confirm, escalate, claim_payment}`.

  There is no void, no refund and no carrier access.
- **What the model sees:** issue codes, the line count, the fraud decision, score and reasons, and statuses. Never an
  amount, an intent, assessment or shopper ID, a token, an address, a confirmation reference or a correlation ID.
  This is tested on six paths.
- **New stubs behind interfaces:** `OrderStorePort` with an in-memory order store (for `mcp-orders`), and
  `CatalogPort` over the live price and stock tables, never the index (for `mcp-catalog`, #10b).
- **Replay labels:** `data/backend/replay_labels.jsonl` (`BACKEND_DATA_VERSION` 2), derived by rule from the
  exception kind. The other three files are byte-identical.
- **Governance:** register rows for the seven tools; the data-flow and threat-model rows.
- **#20's lows N1 and N2:** fixed in the first commit.
