### Answers to the five questions

**(1) Can a new request in a later turn still become a silent replay? No.**
- Keys are now stored per `(claims.turn, key)`: `services/mcp-catalog/src/northwind_mcp_catalog/cart.py:403-404`
  looks them up and `:419` stores them.
- `turn` is a fresh uuid4 on every mint (`services/common/src/northwind_common/mcp_token.py:129`). It is a required
  claim (`Claims.turn: str`, `:68`), and the server refuses a token without a valid uuid4 there (`:165`). So there
  is no `None` turn that would fold every turn back into one shared key space.
- The assistant mints one catalog token per turn (`services/assistant/src/northwind_assistant/turn.py:309`), and
  every tool call in that turn uses it. A retry inside the turn (the CLI's own, or the model's) therefore still
  replays, while the same key in a later turn is a new change.
- The pass-1 failure path (turn 1 add with K, turn 2 remove, turn 3 add with K again replays) now runs as a real
  add. The other case (a different variant under K in a later turn gets `idempotency_conflict`) is also gone.
- What remains: within one turn the model can still collide with its own key. That outcome is never silent. It is
  either `already_applied` at the top level or `idempotency_conflict`, and the model still has its own keys in
  context at that point.

**(2) Is a replay unambiguous at the top level? Yes.**
- `cart.py:409-414` returns `{"result": "already_applied", "original": {...}, "cart": <view read live>}`. The first
  outcome's `"added"` / `"removed"` / `"updated"` now appears only nested under `original`.
- A fresh write returns its own outcome plus the live cart (`:422`). The old `"replayed"` flag is gone from the
  whole repo outside docs (grep found nothing).
- The assistant's live-value recorder still finds the top-level `cart` in a replay
  (`services/assistant/src/northwind_assistant/tools.py:244`), so this shape change does not regress F2.

**(3) Does the key description match the server? Yes.**
- `cart.py:448-453` says a key is "remembered only within this turn", that the same key is resent only to retry a
  change whose result did not arrive in this turn, and that `already_applied` means the key was already used in
  this turn.
- That matches `:403-419`. The conflict message (`:105`, "...in this turn."), the module docstring (`:32-39`), the
  `_idempotent` docstring (`:378-390`), the `cart_store.py:26,32-38` comments and decision 0019 (diff lines
  412-430) all say the same.
- The description says "letters and digits" while the pattern also allows `-` and `_`. That is a harmless subset,
  not a finding.

**(4) Do the examples or the prompt still invite key reuse? No.**
- All three write examples now use `"<new random key>"` (`cart.py:501, 506, 513`). That text fails `KEY` (`:64`)
  because of `<`, `>` and spaces, so copying it verbatim gets `invalid_idempotency_key` (`:398-399`) rather than a
  collision.
- The description says "never take one from an example" (`:449-450`).
- `services/assistant/src/northwind_assistant/prompt.py` contains no key and no key guidance. Its only N1 line is
  `:43-44`: `A cart result of "already_applied" changed nothing now: never report it as a new change.` That line
  is correct under the per-turn server.
- **N1 needs no `prompt.py` change.**

**(5) Is each point pinned by a test? Yes at the server and prompt-text level. The model's behaviour is not
pinned.**
- (1) `services/mcp-catalog/tests/test_cart.py:785` checks that the same key in a new turn is a fresh add
  (quantity 1 then 2). It would fail if the lookup went back to the bare `key`. `:795` checks that a replay within
  the same turn is `already_applied` and the cart holds one unit. `:809` and
  `services/mcp-catalog/tests/test_chk01_criteria.py:631, 653` check that a conflict within the same turn is
  `idempotency_conflict`. The older idempotency tests were moved into one turn (one token per `calls`,
  `test_cart.py:69-91`).
- (2) `test_cart.py:599` (asserts `already_applied` and the exact `original`), `:705`, `:729` (live price on a
  replay), and `:671`. Also `test_chk01_criteria.py:597, 613`.
- (3) `test_cart.py:827` checks the "only within this turn" wording on the shared `_KEY`.
- (4) The placeholder examples are pinned only by the frozen-surface description hashes
