## Findings (most severe first)

### H2-L1 (low, new): the named-product key list includes the internal, unreleased P0009, so the exception is an existence oracle for its name
- **Where:**
  - `/Users/rapido/Projects/northwind-shop/services/rag/src/northwind_rag/query.py:656-672` (`_product_name_pattern`). Lines 663-671 build a key for every row of `products.jsonl`, with no `visibility` or region check.
  - Used at `/Users/rapido/Projects/northwind-shop/services/assistant/src/northwind_assistant/understand.py:350` (`plan_claim`) and mirrored at `/Users/rapido/Projects/northwind-shop/evals/src/northwind_evals/query_plans.py:66`.
  - Source row: `/Users/rapido/Projects/northwind-shop/data/fixtures/products.jsonl:9`, P0009 "Corvane Ascent Pro Shell". It has `"visibility":"internal"`, `"status":"unreleased"` and `"regions":[]`, and it is the only product that gives the key `Corvane\s+Ascent`.
- **Rule:** hard rule 7 (RAG-11). The rule is about internal-only content reaching shopper callers. No internal document is returned, so this is an inference channel, not a widening.
- **What is wrong:**
  - `names_catalog_product` answers "is this brand plus model word a catalog product?" over the whole catalog, internal rows included.
  - The answer decides whether the shopper's first search is narrowed: colour, size and the live price/availability filter, or the plain search.
  - So a shopper-controlled input switches behaviour on whether a guessed name belongs to an internal product.
- **How it fails (key and behaviour switch confirmed in code; shopper-visible effect unconfirmed, as I cannot run it):**
  1. A shopper sends "Corvane Ascent jackets in Black in M". The message matches the key, so `plan_claim` returns None and the plain search runs.
  2. The shopper also sends a control, "Corvane Zephyr jackets in Black in M". It has no key, so the search is narrowed to Black and M.
  3. Retrieval for the same text is deterministic, and the `Citations` event (`turn.py:293`) returns cited product IDs. So the first message's sources can include other colour and size variants, and the control's cannot.
  4. With a price bound added ("… under $300"), the named message also skips the mcp-catalog `eligible_products` round trip, which shows up as a timing difference.
  5. Repeating this over guessed model words per brand finds the name of an unreleased internal product.
- **Reach:** the attacker must guess the model word, the signal depends on the model's answer and is noisy, and only brand plus the first model word leaks, never the description or the NWCANARY reference. Access scope does not change: the plain search is still audience-, region- and visibility-bound by the token. So this is low.
- **Fix (tightening only):** build keys only from products a shopper can see (`visibility == "public"`). Optionally also skip products with empty `regions`. Add a test that no product with `visibility != "public"` contributes a key, and that "Corvane Ascent jackets in Black in M" is still narrowed.
  - This does not change the current eval or red-team items that name P0009 (EV-095, EV-289, RT-006). None of them carries a colour, size, price or availability filter, so `plan.is_plain` already sends them to the plain search. I am inferring that from their text; I could not run `rules_plan`.

## Answers to the questions

**1. Can the exception or `names_catalog_product` widen access (hard rule 7)?** No.
- The exception can only replace a planned search with the plain search: `plan_claim` returns None (`understand.py:350-351`), and `_first_searcher` keeps the plain token (`turn.py:323-324`).
- The plain search is the caller's existing token-bound scope (audience, region, visibility).
- `names_catalog_product` returns a bool only. Its input is the shopper's own message, and no catalog text reaches a token, a prompt or a reply.
- The one hard-rule-7 problem is the existence oracle, H2-L1.

**2. Can it let card data reach Haiku or a token (hard rule 1)?** No.
- Haiku is still called for a routed named message, and that path is unchanged: `query_ok` is checked first (`understand.py:249-252`), after the gateway's `checked_message` (`chat.py:84-87`).
- On a named message, the exception removes the claim entirely, so less reaches a token, not more.
- `part_texts` only lists texts that came through `validate_plan` and `_parts_safe` (card-shaped parts refused). They end up as frozen-vector keys and vectors in `data/embeddings`, which `make scan-cassettes` scans.
- No PAN appears in the diff's tests.

**3. ReDoS?** No.
- The pattern is `\b(?:alt1|alt2|…)\b`, IGNORECASE. Each alternative is `re.escape`d literal words joined by `\s+`.
- Each `\s+` is followed by a literal non-space character, and there are no nested or adjacent overlapping quantifiers. So backtracking at one start position is bounded by one whitespace run times the alternatives that share that prefix.
- Whitespace runs after different brand words do not overlap, so the total work is about O(n × alternatives).
- Messages are capped at 2,000 characters (`chat.py:40`, `:52`), which bounds the worst case at a few hundred thousand simple steps.
- Fixture metacharacters are escaped, and the pattern is compiled once (`lru_cache`).

**4. Can the vouch-list change let a planted vector pass integrity (decision 0012)?** No.
- `_vouch` (`cli.py:847-867`) re-embeds the text behind every added key with the local model and refuses any vector outside `VOUCH_TOLERANCE`. `_frozen_texts` (`cli.py:841-844`) only widens which texts may be vouched.
- So cassette content can at most get a vector vouched that is the model's own embedding of a validated part text (at most 3 parts of at most 200 characters, not card-shaped). That is the same vector a live embed would give, so it cannot rig a ranking.
- `cmd_embed_cache` still refuses a query whose key equals a chunk's key (`cli.py:768-771`).
- The decision 0012 residual is unchanged: a PR that changes the vouch code and adds vectors together is visible only through `make ship`'s control-surface listing.
- One thing is new, for the record only: the vouch list now also moves with cassette content, which a routine row may add. Because vouching checks the vector values, this does not open a hole.
- **Failure behaviour:** a replay miss or failure inside `_frozen_queries` raises `SystemExit`. That is not caught by `cmd_integrity`'s `except RuntimeError`, so `make eval-integrity` and `make embed-cache` exit non-zero. They fail closed.
- I did not re-review the 5 added `data/embeddings` keys; they are not in this diff.

**5. Can `part_texts` spend or reach the network?** No.
- `planner` hard-codes `proxy_config("replay", suite, …)` (`query_plans.py:114`). For any mode other than record or live, `proxy_config` returns a `ProxyConfig` with no `upstream_url`, no `key_loader` and no runner claim (`runner.py:705-706`). A miss is answered locally, and the planner raises `SystemExit` (`query_plans.py:125-136`).
- `suite` only picks the cassette directory; it cannot pick the mode.
- `Understander(live=False)` is passed explicitly, so `LLM_MODE` is not read. Its client is `anthropic_client(base_url)`, which forces `PLACEHOLDER_API_KEY` (`llm.py:250-256`), and `base_url` is the local replay proxy.
