## Design

**Two triggers, both deterministic, both before any search or model call**
- **Button.** "Talk to a person" in `Chat`, always shown. It calls `POST /api/handoff`.
- **Message.** `asks_for_person(message)` in a new `northwind_gateway/handoff.py`:
  - It is pure code: NFKC, casefold, punctuation folded, then a closed list of phrases ("talk/speak to a
    person/human/someone real", "real person", "customer service", "representative", "live agent", "connect me
    with ...").
  - It also has a closed list of exclusions: negations ("don't want a person"), and "agent" or "person" used
    about a product ("travel agent", "two-person tent").
  - `chat.py` calls it after `checked_message`, so card data is still refused first (hard rule 1). On a match
    it emits SSE `handoff` {notice} and `done`, and never calls `stream_answer`: no search, no model call
    (**phase B**). The portal then makes the same `POST /api/handoff` as the button, so there is one queueing
    path and one transcript source.
  - `prompt.py` and `turn.py` are not changed. A handoff message never reaches the model, so no assistant
    cassette changes.

**`POST /api/handoff` (new router, gateway `handoff.py`)**
- Body: `{turns: [{role: "shopper" | "assistant", text}]}`.
  - At most 10 turns, each at most 2,000 characters, `extra="forbid"`.
  - The turns are the shopper's own transcript, held in the portal, as shown on screen. They are untrusted.
- Card data in any turn: the same fixed 422 refusal as chat. Nothing is stored and nothing reaches Care.
- Errors: the structured envelope with fixed text (hard rule 10).
- Caller from the server only (`shopper_caller`): region, session and `shopper_id`. `/api/handoff` joins
  `SESSION_PATHS`. Without a session, it fails closed with a fixed 503.
- **Identity:**
  - Signed in: `shopper_id`.
  - Otherwise: `session_ref`, an HMAC of the session ID under the derived session key with the label
    `northwind-handoff-v1`. The raw session ID never enters a case, a log or a model input.
  - Region from the caller in both cases.
- **Order:** only an `O\d{6}` named in the turns that the order store shows belongs to the signed-in shopper.
  An anonymous caller, or another shopper's order, gets no order. This is not an oracle: the response is the
  same either way.
- **Answer:** 202 `{status: "queued", reference: "H000001", notice}`, at once. The Care run happens after the
  response (below). The notice is fixed text.
- **Idempotency (hard rule 9):**
  - The key is `handoff:<identity>`: one open handoff per shopper or session. A second press or a matched
    message returns the same reference and queues no second case.
  - The queue fake takes `dry_run`.

**Backend: `northwind_backend/handoff.py` (new)**
- `HandoffRequest`: identity, region, trigger (`button` | `message`), order ID or none, cart snapshot or none,
  turns.
- `HandoffCase`: what SA-06's acceptance lists:
  - identity
  - intent
  - root cause
  - amounts
  - recommended action
  - plus the summary and its label, flags, `order_case_id`, `reference` and `correlation_id`.
- **Intent: code, from a closed set:** `order_issue`, `return_or_refund`, `delivery`, `payment`,
  `product_question`, `other`.
  - `intent_of(turns, order)` uses keyword rules over the screened shopper turns.
  - The intent is never model text, so injected text cannot set it.
- **Root cause:**
  - With an order: BE-07's (`root_cause_of`).
  - Without one: `shopper_requested`.
- **Recommended action:** a code table keyed on intent and root cause. With an order it extends BE-07's
  `RECOMMENDED`.
- **Amounts:**
  - With an order: BE-07's `CaseAmounts`.
  - Without one: the live cart's lines and total, from `CartReader`, read by the gateway at request time and
    labelled `cart at handoff` (hard rule 2: a live tool, never model text).
  - An empty cart, or a cart that cannot be read: the flag `no_amounts`.
- **`HandoffDesk` port and in-process adapter:**
  - `request(idempotency_key, request, dry_run)` reserves the reference and returns it. It then runs Care as
    an `asyncio` task: it keeps a reference to the task, and a failure is caught and audited.
  - **With an order:** `run_care(CareTask(order_id, turns))`, exactly as BE-07 builds it. The BE-07 case goes
    to `CaseQueueFake`, and the handoff case points to it.
  - **Without one:** the summary-only Care variant.
  - The handoff case goes to a `HandoffQueueFake`, which shares `fakes/_base` card-data refusal and
    idempotency.
  - If Care fails, the case is still queued with the code fields and `summary_missing`, so staff can act
    without the transcript.
  - Audit events come through BE-08's `AuditContext`.
- **The model never gets a write:** `create_case` and the handoff queue are called by code only, as in BE-07.

**BE-07 change, `agents/care.py`**
- `CareTask.order_id` becomes optional.
- With an order ID: the system prompt, tools, schemas and prompt text stay byte-identical. A test hashes them
  against main's, and the existing `backend-care` cassettes must still replay.
- Without one: `SYSTEM_PROMPT_NO_ORDER`, with only `submit_summary`. The same transcript screening, masking
  and summary checks apply.

**Portal**
- `chatStream.ts`: a new `handoff` event, added to the exhaustive event maps that the #14 tests require. Also
  `requestHandoff(turns)`.
- `Chat.tsx`:
  - Keeps the last 10 turns, as shown, for the handoff only.
  - Adds the "Talk to a person" button.
  - Calls `requestHandoff` on the button or on a `handoff` event.
- `HandoffNotice.tsx`: states `requesting`, `queued`, `failed` (with a retry), and a `joined` stub.
  - `queued` text: "You asked for a person. Someone from Northwind's care team will take over this chat
    (reference H000001). Until they reply, you're still chatting with an AI assistant."
  - `joined` text: "A person from Northwind's care team has joined this chat." It is driven only through a
    `HandoffStatus` interface whose one implementation is a test fake.
  - `AiDisclosure` is unchanged and stays on screen in every state.

**Pin: no case tool for the assistant (your hard constraint)**
- A new test, `services/assistant/tests/test_sa06_no_case_tool.py`. It reads code; it changes nothing.
  - For anonymous and signed-in turns, `assistant_options(...)` gives `allowed_tools` and `mcp_servers` with
    no name containing `case`, `handoff`, `escalat`, `assign`, `ticket` or `staff`.
  - `tool_scopes.AGENT_TOOLS` for every shopper-audience agent has none either.
  - The Care agent's `allowed_tools` excludes `create_case`.
  - Nothing in the gateway's handoff module is reachable from a model: it imports no SDK and builds no
    `agent_options`.
- `tool_scopes.py` itself is not edited, because CHK-07 changes it. Adding `case` to `FORBIDDEN_FRAGMENTS`
  waits for phase B.

## Approved, with four changes (the user, 2026-11-26)

   database, no window. `make check` runs only when no other window is running `make ci` or recording.
2. **The trigger's labelled set** (`handoff_phrases.jsonl`: ≥40 positives, ≥40 near-misses):
   - A fresh subagent drafts it from a short guide, before the matcher exists.
   - It is pinned by sha256 before the matcher is written.
   - The first score is reported as the honest one. One fix round is allowed, and it is reported as in-sample.
   - **Target:** 0 false handoffs on near-misses, and at most 2 misses on positives. A miss falls through to
     the assistant as normal. This replaces the 100% requirement above.
