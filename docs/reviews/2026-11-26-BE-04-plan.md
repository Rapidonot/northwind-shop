## Changes (new code in `services/backend/src/northwind_backend/inventory/`)
1. **`InventoryPort`** in `ports.py`, with `reserve`, `release` and `commit`. Two implementations share one contract test:
   - `PostgresInventory`, in `postgres.py` with `schema.sql`, using `psycopg`.
   - `InventoryFake`, in-memory, in `fakes/inventory.py`, holding a lock, for unit tests and the replay harness.
   - `AuditedInventoryPort`, in `views.py`, writes the audit events (BE-08).
2. **Schema:**
   - `inventory_stock(variant_id, node, region, on_hand, held)` with `CHECK (held >= 0 AND held <= on_hand)`.
   - `inventory_holds(idempotency_key UNIQUE, order_id, variant_id, node, qty, status held|released|committed|expired, expires_at)`.
3. **`reserve(order_id, lines, region, postal_code, idempotency_key, now, dry_run=False)`**, one transaction per order:
   - Pick the node (item 5).
   - For each (variant, node), in sorted order so concurrent orders can't deadlock:
     - `SELECT … FOR UPDATE` on the stock row.
     - Expire that row's holds with `expires_at <= now` (status `expired`, `held -= qty`).
     - The conditional `UPDATE … SET held = held + q WHERE … AND on_hand - held >= q RETURNING`.
   - All or nothing.
   - The key goes in with `ON CONFLICT DO NOTHING`, so a repeat returns the first result, including after a soft-decline retry.
   - `now` is injected by the caller and the database's own clock is never used (change 2). The hold is fixed at `HOLD = 15 min`.
4. **`commit` is an addition to the user's reserve and release**, named here (advisor F6). Without it, a placed order's units come back when the hold expires, and nothing stops a later oversell.
   - **`release(key, now)`** is idempotent: `held` goes to `released` and `held -= qty`. A second release, an expired hold and a committed hold are each a no-op Ok.
   - **`commit(key, now)`** at capture: `held` goes to `committed` and both `on_hand` and `held` drop by `qty`, so a committed hold never expires.
   - If the hold has already expired, commit tries to re-reserve under the same lock. If that fails it returns business `hold_expired`, and the order is escalated.
   - The ToolError codes `out_of_stock` (business, carrying substitutes), `hold_expired` (business) and `inventory_unavailable` (transient) keep "access failed" distinct from "valid empty" (hard rule 10).
5. **`nodes.py`**: deterministic node choice.
   - Candidates are the region's `stock_nodes` from `regions.json`.
   - Prefer one node that fills the whole order, in a fixed order by postal prefix (US: 0–4 → DC-EAST first, 5–9 → DC-WEST first). The preference order is total, so there is no further tie-break. A US code may carry a `US-` prefix, which the data uses (test-writer finding).
   - Otherwise split per line in the same order.
6. **`substitutes.py`**, code only with no model call:
   - Candidates have the same department and subcategory, the same region and `available >= qty`.
   - Price is within ±20% of the original's live price.
   - Ranked in a fixed order: same product in the same colour and fit, then same size and fit, then attribute overlap, then the smallest price gap, then variant ID.
   - At most 3, returned as variant ID and reason, with no price.
7. **Wiring (change 1), in `agents/orders_place.py`:**
   - `Ports.inventory`.
   - In `authorize_payment`, after the claim and before `payment.authorize`, call `reserve` with key `order_id:inventory.reserve` and `now` from the run's clock.
     - A success returns nothing new to the model.
     - A refusal escalates by code (reason `out_of_stock`) and returns the existing `ESCALATED` refusal text. That changes the tool result, but only in that case.
   - In `capture_payment`, after a successful capture, call `commit`.
   - In `escalate()`, call `release` when this run holds a hold. This covers a hard decline, the second soft decline and every later escalation.
   - The calls go through `_write`, so a doubtful inventory write stops the run like any other.
   - Nothing is recorded as a `RunState` step, so `handoff` and the step results don't change.
8. **Expiry (change 2):**
   - Everything gets its time from an injected `Clock`: the placement uses the run's clock, the tests use a settable fake.
   - No `time.time()`, `sleep` or `now()` in SQL.
9. **M12:**
   - A line with quantity ≤ 0 or a duplicate `variant_id` gives a new issue `invalid_line`, checked before any stock read.
   - Stock is checked against the summed quantity per variant.
   - `Reason` gains `invalid_line`.
   - The prompt is unchanged: "any other issue → escalate" covers the new issue.
10. Dependency: `psycopg[binary]>=3.3.7` in `services/backend/pyproject.toml`. It is already locked for `northwind-rag` and others, so `uv.lock` gains only the backend's dependency lines.
11. PROGRESS row #25, plus these open items:
    - "`check_stock` does not subtract reservations", owner #18 (RECORD-ALL).
    - The CHK-01 switch below, owner #18 or later.
    - A cancel tool calls `release()`, owner #19's `cancel_order`.

## Tests (`services/backend/tests/inventory/`, tagged `req("BE-04")`; M12 tagged `req("BE-05")`)
- **Race, `@integration`, real Postgres, each thread on its own connection, all starting on a barrier:**
  - Last unit: 50 threads, 20 rounds; exactly one hold, and `held = 1`.
  - Mixed: `on_hand = 5` over 2 nodes, 40 requests of 1–3 units; `held <= on_hand` always, and granted = `held`.
  - The same key 10 times concurrently makes one hold.
  - Opposite line orders don't deadlock.
  - Release and commit running alongside reserve never push `held` below 0.
  - Expired holds swept during a race: an injected `now` past expiry frees the units to exactly one new taker.
- **Failing first:** a read-then-write variant, kept only in the test, must oversell under the last-unit race.
- **Contract:** one parametrized suite runs against both `PostgresInventory` and `InventoryFake`. It covers idempotency, `dry_run` holds nothing, the expiry boundary (`expires_at == now` counts as expired), commit after expiry, release no-ops, and the envelope codes.
- **Unit:** node choice, substitutes (filters, fixed order, at most 3, no price), and the database down giving `inventory_unavailable`.
- **Wiring:**
  - Reserve happens before authorize; a refusal means no authorize and an `out_of_stock` escalation; a hard decline releases; capture commits.
  - A doubtful reserve stops the run.
  - **$0 pin (change 1):** every `data/backend/orders.jsonl` order runs through the rule-driven driver twice, with inventory and without. Every tool result's bytes must match. The recorded replay of `backend-replay`, `backend-audit` and `backend-orchestrator` runs in replay with no misses.
- **M12:** duplicate lines that only overflow when summed, quantity 0 and a negative quantity each give `invalid_line`, an escalation and no authorize. A pin checks that no replay order has a duplicate line or a quantity ≤ 0.
