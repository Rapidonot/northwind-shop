## What this does

- **Cart tools (CHK-01, decision 0019).**
  - **The tools.** mcp-catalog has `get_cart`, `add_to_cart`, `remove_from_cart` and `set_cart_quantity`. They are
    keyed on a signed `sid` token claim and the region.
    - Live stock is checked on every add and increase.
    - An out-of-stock add is refused, and the server chooses the alternatives.
    - Every write requires an `idempotency_key` (hard rule 9). There is no `dry_run`.
  - **Access.** The `shopper-portal` agent gets only `get_cart`.
  - **Gateway.** A session cookie, and `GET /api/cart`. The cart is shown in the chat panel.
  - **Prompt.** Cart rules, and no unprompted capability statement.
  - **Evals.**
    - Each item gets its own session, from the item ID, and the cart is reset per item.
    - The judge sees cart results as live values only.
    - A refusal records only the requested variant's stock.
- **The offer-drop rule (RAG-08; decision 0015's amendment).**
  - The output check drops a sentence in which the assistant offers to look up, check or give a price, stock
    or availability. Nothing goes in its place.
  - It keeps strictly to the user's words. "will" and "'ll" are out, so the preamble "I'll check the price." stays.
  - The noun must come within 26 characters of the verb, so each pattern fits `L`.
  - The class is decided when the sentence ends. If another class has a blocking match in the same sentence,
    that class's fixed sentence wins.
  - It changes the shown answer of 21 eval items. W6 re-judged those.
- **Tool results in `tool_use` order (FOUND-2; decision 0001's amendment).**
  - The cause: the Claude CLI runs read-only tools in parallel and appends their results as they finish, so a
    replay could miss on timing. Evidence: `docs/reviews/2026-11-23-16-tool-order-probe.txt`.
  - The proxy now reorders each user message's tool results into the preceding `tool_use` order. It keeps
    `cache_control` in its slot, and re-serializes only if something moved.
  - It does this before it scrubs, hashes, logs, scans, prices or forwards anything. A test pins that the
    scrubber, the secret and PAN scan, and the ledger all see the forwarded bytes (the user's condition).
  - `miss_diff` compares a miss with the same test's cassettes first, so a miss is reported in seconds.
  - No assistant-side lever worked without changing a control or a contract. The concurrency setting did not
    serialize the tools, hooks do not run under `--bare`, and the read-only hint is pinned by contract tests.
- **`ship` waits for CI to start (AUTO-1; the user, under decision 0021).**
  - DEV-1 removed the push trigger, so `gh pr checks --watch` returned at once on a new PR (PR #48).
  - `check_jobs` now polls until every `REQUIRED_JOBS` entry has a check, before `--watch`. That list includes
    main's new `CI/python-integration`.
  - The wait is at most 600 s, polled every 15 s. `SHIP_CHECKS_WAIT` and `SHIP_CHECKS_POLL` can only shorten it.
