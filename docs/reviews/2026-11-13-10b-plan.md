## 3. Decisions for the user

- **D1. Which agent is scoped to the catalog tools.**
  - **Recommended:** give `shopper-assistant` the five tools on `northwind-catalog` in
    `northwind_common.tool_scopes`, which matches PRD §7.
  - This is not attaching them. The assistant reads its own `ALLOWED_TOOL`
    (`services/assistant/src/northwind_assistant/turn.py:102`), not `tool_scopes`, and gets no catalog URL
    or token. With L4, its rag token is refused by mcp-catalog anyway.
  - Why: the contract tests can then prove C7 and C8 with real shopper tokens over HTTP.
  - Cost: `services/common/tests/test_tool_scopes.py::test_the_assistant_gets_exactly_retrieve_context_and_no_resource`
    changes from rag-only to rag plus the five catalog tools. That pins a wider scope, so it counts as a
    planned test change, named here.
  - Alternative: no agent is scoped, and C7 and C8 are proven at handler level only.
  - `catalog-subagent` gets `northwind-catalog: frozenset()`, because PRD §7 gives it catalog writes, not reads.
- **D2. Where "live" prices and stock come from (amended by the user at approval, 2026-11-13).**
  - `LiveCatalog` is an interface with reads plus `set_price` and `set_stock`. Tests use the setters now
    and the backend later; #12 (RAG-09) must change price and stock while the server runs.
  - `FixtureCatalog` runs `verify_dataset` when it seeds itself, and refuses to start on a mismatch. It
    then seeds an **in-memory store** from the verified files: `products`, `variants`, `prices` and `stock`.
  - Every tool reads the store on each call. There is no snapshot cache.
  - `set_price` and `set_stock` are not tools and cannot be reached over MCP. A contract assertion pins
    the catalog listing to exactly the five read-only tools.
  - No Postgres tables, so nothing touches the shared database. Postgres-backed live tables are logged,
    no owner.
- **D3. Extra argument keys.**
  - **Recommended:** mcp-catalog **refuses** an unknown key (`validation`, `unknown_argument`) and checks
    card data in every argument value.
  - This differs on purpose from mcp-rag, where extra keys stay ignored by the user's 2026-11-10 decision.
    New code fails closed. mcp-rag is unchanged.
- **D4. Q4's "mcp-rag reports it".**
  - **Recommended, no migration:**
    - `dataset_verified` is `true` only when the current index's stored `dataset_sha256` equals the hash
      verified from the server's fixtures directory at read time.
    - It is `false` on any mismatch or error, never an error itself.
    - Rows published by the old ingest are reported honestly, and the shared database needs no new
      column and no re-ingest.

### `data/src/northwind_data/ingest_guard.py` (Q4)

- `verify_dataset(fixtures_dir) -> str`:
  - Hash every file in `manifest["files"]` from disk, in the manifest's order, the same way
    `generate.py:63` does.
  - Compare each file hash, then recompute `dataset_sha256` and compare it.
  - On any mismatch, or a missing or extra-path entry (no `..`, no absolute path), raise
    `DatasetMismatchError`, which names the file, never its content.
  - `_answer_key.json` is hashed as bytes and never parsed.

### `services/rag/src/northwind_rag/ingest.py` (Q4)

- `ingest()` and `ingest_enriched()` call `verify_dataset` **first**, before `build_chunks`, migrations or
  any write. A mismatch aborts with no change to the index.

- `Backend` gains `fixtures_dir: Path` with the repo's `data/fixtures` as default, so positional callers
  are unchanged.

### `services/mcp-catalog/` (new package `northwind-mcp-catalog`; C2, C4, C7, C8, HR2)

- `live.py`: `LiveCatalog` protocol plus `FixtureCatalog`:
  - It loads after `verify_dataset`.
  - Products and variants carry visibility. Prices are exact minor units from `prices.jsonl`, and stock is
    summed per region from `stock.jsonl`.
  - It imports neither `northwind_rag` nor `psycopg`.
- `tools.py`, the five tools:
  - Each is read-only (`readOnlyHint`), with a closed schema and no caller keys.
  - Each description says when not to use it, with an example (contract rules).
  - **Caller from the token only:** audience decides the visibility filter, and region decides price and
    stock.
  - `search_products`:
    - Structured filters: `category`, `department`, `subcategory`, `brand`, `gender`, `colour`, `size`,
      `fit` and `text` (a name substring). All are enums or bounded strings.
    - `limit` 1–20, default 10, ordered by product ID.
    - Returns summaries: ID, name, brand, category, department and subcategory. No description and no
      price; price bands stay out too.
  - `get_product(product_id)`: attributes, sizes, colours and variant IDs.
  - `get_variant(variant_id)`.
  - `check_stock(variant_id)` → on hand in the token's region.
  - `get_price(variant_id)` → amount (decimal string) and currency in the token's region.
  - **C7, no existence oracle:**
    - For a shopper, an internal product or variant gets byte-identical results to an unknown ID: a
      `validation` `not_found` with fixed text.
    - Search silently excludes internal products.
    - A staff caller sees them. No staff agent is scoped (D1).
  - **Errors (C4):** all fixed text, never echoing an argument.

    | Case | Category | Code |
    |---|---|---|
    | Malformed ID | `validation` | `invalid_product_id` / `invalid_variant_id` |
    | Unknown key (D3) | `validation` | `unknown_argument` |
    | Card data in any value | `validation` | `card_data_refused` |
    | Unknown or internal ID | `validation` | `not_found` |
    | Not sold in the region | `business` | `not_sold_in_region` |
    | No region on the token | `validation` | `region_required` |
    | Anything unexpected | `transient` | `tool_failed` |

    No match is a valid empty result, not an error.
  - Success is JSON text only, sorted keys and no `structuredContent`, as in mcp-rag (S0 item 5).
    Labelling it as data for the model is #12's (hard rule 6).
- `server.py`: `CatalogServer`, the same shape as `RagServer`:
  - scoped listing; a refusal looks the same for an unscoped tool and a missing one;
  - the error envelope;
  - no `instructions`;
  - the shared gate bound to `northwind-catalog`;
  - logs name only categories and codes.
- `app.py`: `python -m northwind_mcp_catalog.app` on `127.0.0.1:mcp_catalog_port()`, one worker. It refuses
  to start without `NORTHWIND_MCP_TOKEN_KEY` or on a dataset mismatch.
- `testing.py`: `running()` and `token(..., server=)` helpers.
