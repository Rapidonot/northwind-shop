## What it does
- **PRD BE-07:** "Care agent builds an escalation case (summary, root cause, amounts, recommended action) and queues
  it for staff." Acceptance: "Staff can act on a case without the transcript."
- **The model's job:** the Care subagent (Haiku, through `agent_options()`) writes only the summary. It has two tools:
  - `get_order`, read-only and bound to the task's order (another order ID is refused and audited);
  - `submit_summary`, checked by code; it writes nothing.
- **What code fills in, from tool data:**
  - the order fields and the order's lines;
  - the amounts (what the order's payment claim reported);
  - the root cause (the store's reason code);
  - the recommended action, from `agents/escalation.py`. That is the Orders agent's table, moved here with its 12
    entries byte-identical (sha256 pinned), plus `not_escalated`.
- **Queueing:** code queues the case through `CasePort.create_case`, keyed `care:<order_id>:<root_cause>`. The port is
  an in-memory fake until `mcp-cases` exists. A retry with another summary returns the first case.
- **No total:** there is no catalog read (the user's decision), so every case is flagged `total_unavailable`.
- **The transcript is untrusted** (hard rules 1 and 6):
  - turns that hold card data, alone or together, are withheld whole;
  - every other number of two or more digits is masked as `[number removed]`, except the task's own order ID and ISO
    dates;
  - the text is read in NFKC form without control, format or combining characters after a digit;
  - it reaches the model as labelled data.
- **The summary is refused** for card data; a money figure (a sign; one of 32 codes in capitals next to a number; a
  currency word; a two-decimal amount); any web address; an email address; control or format characters; or more than
  600 characters.
- **Audit (BE-08):** `care.run`, `order.get` and `case.create`, with one correlation ID. The transcript and summary are
  recorded as type and length only.
- **Demo:** `uv run python -m northwind_backend.care O000002 transcript.json --escalated-as fraud_review`.
- **BE-01's `escalate_to_care`:** not wired; the Care agent is standalone, as planned. Owner: Window B's staff caller.

## Open lows (PR body only, decision 0021)
- **F3:** a security code written "1, 2, 3" (comma and space) in one turn gets past `cards.py`'s CVV check. The dotted
  and slashed forms are masked here. This fits #18's scanner widening (FOUND-2 review 6).
- **F4:** lowercase currency codes ("usd 45") pass the summary check, per the user's N4 decision.
- **F5:** masking also removes variant IDs, 2-digit sizes and non-ISO dates. So a summary on a multi-line order can't
  name the line; the case lists the lines.
- **F6:** in `agents/care.py`, the pin doesn't pair each view class with its own set. Each view enforces its
  allow-list at runtime.
- **Residuals:**
  - Single digits separated by words, digits spelled out, and the two free digits of each kept ISO date are not masked.
  - The case queue fake doesn't catch a card number split across case fields that are far apart. Only the summary is
    free text today (advisor F-A).
- **Stricter than option (b) as worded, for the user's acceptance (advisor F-B):**
  - Only the task's own order ID is kept, not every `O\d{6}`, so a summary can't name another order.
  - Digits joined by one non-alphanumeric character count as one number, so "1/2", "3-4" and "10.5" are masked.
  - With F5, a summary can't name another order or a line.
- **L4 consequence (the user's decision):** a retry after a case with no summary returns the first case with its code
  summary. Under the `not_escalated` key, a later complaint about the same order gets the first case back.
