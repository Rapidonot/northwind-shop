## What was built

**The gate (C1, C2).** Every route under `/api/staff` exists only when `DEMO_STAFF_DASHBOARD` is exactly `"1"`.
- Off: every staff path, under any method, gets exactly the unknown-path 404. An ASGI gate (`StaffGate`) decides this
  before routing, so no trailing-slash redirect or 405 shows the console is there (security review L1). The route guard
  stays behind it, and no store is read.
- On: only GET on an exact view path; `Cache-Control: no-store`; no session or cookie; no write anywhere.
- The portal's `#/staff/<view>` asks `/api/staff/overview` first and loads the console's chunk only on a 200. A 404
  shows the shop's own not-found page.

**The look** (`docs/design/staff/staff-01…08.png`, renamed to ASCII). The user approved it after three agent-map
rounds. It follows the shop's Bold utility rules unchanged (`theme.test.ts` passes as it was):
- escalated is filled ink, not the accent;
- table heads are not uppercased;
- the header says "Demo console · read-only", never "Signed in as staff".

**The agent map (C3, C4).** Generated on each read (`staff/agent_map.py`), never hand-written:
- MCP servers, their tools and edges come from `tool_scopes.AGENT_TOOLS`.
- The catalog's cart writes fold into "+ cart write tools", from `CART_TOOL_NAMES` less `get_cart` (pinned equal to
  `CART_WRITE_TOOLS`).
- Each AI agent's model is the `llm.py` constant its own module imports and uses (AST), labelled from the value.
- Every other edge stands on an import that must be in the code; take the import away and the edge goes.
- Drawing: one SVG (viewBox 1160×778) from the layout table `apps/portal/src/staff/layout.json`, measured from the
  reference. Generated nodes and edges match its boxes and routes both ways, in both test suites.
- The portal's snapshot `system.json` is pinned equal to what the gateway serves.
- Every text line is tested to fit its box at the size it renders. The tool lists once rendered at 13px through a stray
  CSS rule (failing first: `docs/reviews/2026-11-27-OPS-1-failing-first.log`).
- The order band shows what runs today (the user's choice): "Staff request (command)" → orchestrator → read-only
  orders and returns subagents, and "Escalated order (command)" → escalation → Care agent. The reference's order lane
  matched no path in the code.
- Two real MCP hops are drawn beyond the reference: Pay (demo) → catalog (`get_cart`, `remove_from_cart`) and Talk to
  a person → catalog (`get_cart` with no order). The handoff lane drops "no MCP", which that hop makes untrue.
- The assistant never reaches the orchestrator, and Pay (demo)'s path has no AI; both are tested on the graph and in
  the code.

**Sample traces (C5).** Four, marked sample, no timings. Each walks the map's lines from its entry, including every hop
a real request takes. The damaged parcel uses O000800, the demo shopper's only delivered order, and lights the chat part
first, then "if the shopper presses Talk to a person" and the handoff.

**Real data (C6, C7).**
- Orders: the 1,000 seeded orders, seeded as northwind-orders seeds them. Each shows northwind-orders' own shopper
  status (pinned equal, order by order) and its exception as the reason, giving 50 escalated, 900 with no exception
  and 50 recovered.
- Pay (demo) orders are added. An escalated one shows the checkout's own escalation code as its reason (for example
  `fraud_review`), and counts under that code.
- The handoff desk's escalation cases appear as part of each handoff, not as a separate list.
- Driven for real, with no store override (`sa01_checkout/test_ops1_staff_wiring.py`): a Pay through the real routes
  reaches the console's orders, activity and stock through `app.py`'s provider, and a fraud review shows escalated with
  its reason. The handoff desk the app builds registers the stores the console reads. The handoff route itself runs the
  Care agent, a model, so the SA-06 tests cover it instead.
- Read-only by AST: no staff module calls a store write (`test_ops1_readonly.py`).
- Handoffs, agent activity and live holds come from this process's in-memory stores, "since this server started".
- A handoff has no time: the queue keeps none, so none is shown.
- Internal-only products are left out of every view (hard rule 7).

**The screen (C8).** Every string leaving `/api/staff` is screened:
- card data, its NFKC form included;
- key-shaped secrets, by the cassette scanner's own patterns, copied (the gateway never imports
  `northwind_llm_replay`; pinned);
- the answer key's internal canaries; if the answer key cannot be read, every view is a structured 503 (fails closed,
  L5).

**Hard rule 9 and SA-01's pin.** The views read the checkout's stores through a provider `app.py` registers, never the
checkout module, so SA-01's pin (only `app.py` imports `checkout.py`) passes unchanged. `app.py` builds the checkout
desk once at import, so the console's threadpool reads cannot race Pay into building a second desk (L2). The handoff
desk registers its stores the same way.

**`app.py` changed beyond the plan's one `include_router` line.** The plan said `app.py` gains one line; it gains
five changes, each for a reason found in the row:
1. `app.include_router(staff_router)`, as planned.
2. One `from northwind_gateway import checkout` import, which replaces `from northwind_gateway.checkout import router as
   checkout_router`. SA-01's pin counts import statements, so `app.py` must stay the only, single importer of
   `checkout.py`.
3. `_checkout_stores()` and `staff_views.use_checkout(...)`. They give the console the checkout's stores without the
   checkout module, keeping SA-01's pin (no other module can reach the confirmation issuer).
4. `checkout.checkout_desk()` and `demo_orders()` at import (security review L2; advisor-reviewer finding 5 for the
   second). The console's reads run in the threadpool, and
   `functools.cache` would let two threads each build a desk, losing Pay's idempotency record on the first. Building
   it opens no database connection:
   - the desk is in-memory fakes, `shoppers.jsonl` and `stock.jsonl` read into memory, the in-memory `InventoryState`
     (never `PostgresInventory`) and an in-memory audit sink;
   - the gateway's only database call is the health route's, per request;
   - `test_importing_the_app_builds_the_desk_without_a_database` imports `app.py` in a fresh process with
     `DATABASE_URL` on a closed port, and asserts the import succeeds with one in-memory desk built;
   - the Pay tests pass on their own: the SA-01 checkout unit tests, `test_chk01_gateway_criteria.py`, mcp-catalog's
     `test_chk01_criteria.py` and the assistant's `test_chk01_assistant_criteria.py`.
5. `app.add_middleware(StaffGate)` (security review L1). It decides every `/api/staff` path before routing.

**The two other gateway files outside `staff/`.**
- **`handoff.py`:** adds `HandoffStores` and `handoff_stores()`, a read-only registry. `handoff_desk()` builds its
  handoff queue, case queue and audit sink as before, and now also keeps a reference to them, so the console reads
  the desk's real stores. It does this without reaching into the backend desk's private attributes, and without
  editing `services/backend` (a protected path). Nothing about the desk's behaviour changes; the registry only hands
  out the same objects for reading. It is `None` until the first handoff builds the desk, which the console shows as
  an empty view.
- **`demo_orders.py`:** adds `DemoOrders.everyone()`, which returns copies of every shopper's Pay (demo) entries
  under the store's lock. Until now there was only `of(shopper)`, one shopper's orders, and the console's Orders &
  escalations view needs all of them. Copies, so a reader cannot change the history.

**The staff routes are registered GET only**, and `/api/staff/orders` is on CHK-01's approved route list as GET only
(the user's tightening for advisor-reviewer finding 6). CHK-01's pin now reads `app.routes`, included routers and
`include_in_schema=False` routes too, not `app.openapi()`. It failed first in two ways, both in the failing-first log:
- a planted hidden POST order route that the old pin could not see;
- the staff routes as registered at `bd438d3`, for every method.

`StaffGate` already answered every non-GET staff request with the unknown-path 404 before routing, so the behaviour
does not change. `test_chk01_gateway_criteria.py` is an existing file changed in this row: this one pin is tightened,
nothing is loosened.

was deleted after the merge from main (below); the gate report checks the diff's file list against the freeze list.
