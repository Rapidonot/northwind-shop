## What this does

- **`services/mcp-rag`, a real MCP server (CC-10).** It serves `retrieve_context` and an index-manifest resource
  over streamable HTTP on 127.0.0.1, with the SDK's DNS-rebinding protection, behind a token gate.
  - Any request without a valid per-turn token gets a bare 401 before MCP runs. The token is HMAC-SHA256 over
    `aud`, `region`, `agent`, `turn` and `exp` (at most 120 s), signed with `NORTHWIND_MCP_TOKEN_KEY` from the
    environment.
  - Audience and region come only from the token, never from arguments. Extra argument keys are ignored and never
    change who is searching (the user's decision, 2026-11-10).
  - Each agent sees only its tools in `northwind_common.tool_scopes` (PRD §7). A tool outside the scope gets the same
    `permission` error whether or not it exists.
  - Every error is the structured envelope (`isError`, `errorCategory`, `isRetryable`, `message`, plus a `code`), with
    protocol `isError: true` and fixed text. A valid empty result is `NO_SOURCES` with `isError: false`.
  - The server holds RAG-10's cap: 3 searches per token turn, the gateway's first search included (decision 0007).
  - The manifest counts chunks for the caller's audience only and states `dataset_verified: false` (Q4). Only the
    staff `catalog-subagent` scope may read it; the assistant gets no resource.
  - The server has no `instructions` and no SQL of its own.
- **The assistant searches through mcp-rag.** The in-process tool is gone. The gateway's first search and the model's
  refinements both call `retrieve_context` on mcp-rag, with one per-turn token minted from the server-built caller.
  - The CLI gets the token, never the key. `agent_options()` always adds `--strict-mcp-config`.
  - `seen` and `failed` come from the server-rendered `<source id>` lines and the envelope's `code`, for both searches.
  - **Q2 and Q6:** a first search that fails for any reason but validation (unreachable, 401, 5xx, a transient,
    permission or business result) ends the turn with `retrieval_failed` and no model call, logged by category only.
  - The MCP client loggers are held at WARNING, because the client logs request arguments at DEBUG (the user's
    addition).
  - The tool surface is frozen: name, description and schema hash against a golden list (Q5).
- **The ranking-only pin is tightened first (C1).** No raw SQL on `rag_chunks` outside `retrieval.py` and `store.py`,
  no chunk dumped whole and no new `Chunk` importer, by full path over every source root. Written to fail first, it
  caught `embedding.py`'s frozen-vector query, which moved unchanged into `store.py`. 12 mutants are killed.
- **Wiring.** `make dev` makes a fresh key per run and starts `dev-mcp-rag`, `dev-gateway` and `dev-portal` (the
  portal without the key). Playwright starts mcp-rag with a key from `crypto.randomBytes`. No workflow change.
- **Split by the user's decision:** mcp-catalog is row #10b (`req/10b-mcp-catalog`), added to `PROGRESS.md` with C2,
  C7 and C8 (catalog) moved verbatim. **CC-10 stays partial:** the policy-catalog resource belongs to mcp-policy.
