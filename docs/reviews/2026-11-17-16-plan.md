## 2. Decisions (recommended; please confirm)

- **D1. The cart lives in mcp-catalog** (`northwind_mcp_catalog/cart.py`, its own scope set). PRD §7 lists
  cart tools in the Shopper Assistant's row next to the catalog reads, and gives the catalog subagent only
  "catalog write tools", so the cart is scoped apart from both. The deciding fact is that the live store
  is per-process memory (`FixtureCatalog`). A separate mcp-cart would hold a second store that
  `set_stock` never reaches, or it would have to call `check_stock` over MCP between servers. In
  mcp-catalog, the stock read and the cart write happen under one store lock. Cost: mcp-catalog is no
  longer read-only, and its docstring and the tool register say so. Alternative: a new `northwind-cart`
  server (a new port, token, Playwright server and dev entry), which needs a cross-server stock call.
- **D2. Identity: an anonymous session the gateway signs.** An ASGI middleware on `/api/*` gives a request
  without a valid cookie a new 128-bit session id. The cookie is `nw_session`, HttpOnly, SameSite=Strict,
  Path=/api, with an HMAC under a key derived from `NORTHWIND_MCP_TOKEN_KEY` (label `northwind-session-v1`),
  so no new secret is needed. `current_caller` adds `session` to `Caller`, and the MCP token gets a `sid`
  claim. The cart is keyed on `(sid, region)` from the verified token, and no schema takes a cart, session
  or shopper ID. Alternative: one dev session from server config, like `DEV_SHOPPER_REGION`. It needs less
  code, but every tab would share one cart.
- **D3. Panel source: `GET /api/cart`.** The gateway calls `get_cart` itself, as a new agent `shopper-portal`
  (shopper audience, `get_cart` only). The portal fetches the cart on mount and after each turn ends. The
  panel never shows anything the model wrote.
- **D4. Recording order (§6):** record smoke, redteam, a2a-05-partner and cart after the main merge that
  brings in #32, not before. See §6 for why.
- Decision record `docs/decisions/0019-cart-tools-and-session.md` (0018 is #32's; 0017 is the last in the
  tree) covers D1–D3 and the token claim.

## Addendum 8: the offer-drop rule (the user, 2026-11-23, after W5 stopped on EV-092)

**Why.** W5 (`eval-answers`, 308 items) stopped on EV-092's containment. The answer was contained in substance,
but it ended with "Do you want me to look up the current live price for the Wren Bath Towel?", and the judge
counted that as an unsupported product claim. Option A (a known-failures entry) is withdrawn: the payload stop

**Rule, in the user's words** (PROGRESS.md, the ordering note): drop sentences in which the assistant offers to
look up, check or give a price, stock or availability. Deterministic and fail-closed, with no replacement
sentence. Not dropped: a reported live value ("The live price is ..."), a past-tense report ("I checked ...").

**How the words become patterns.** This takes no wider reading than the user's words. The user decides two open
points at this approval.
- **Verbs:** look up, check, give. "give" includes "give you".
- **Nouns:** price or prices, stock, availability, within 26 characters after the verb and in the same sentence (26, not the first draft's 30: the width test caps the "want/like me to" frame at 26 under `L`; measured at coding).
  The window keeps every pattern within `L` = 64, which the existing width test checks.
- **Offer frames:**
  - "I/we can, could, may or would VERB ...";
  - "want me to / like me to VERB ...";
  - "shall, should, can or may I VERB ...".
  These cover the user's three examples: "I can look up the live price of X", "I can give you its live price"
  and "Want me to check stock?".
- **Decision 1 (advisor finding 1, high): "will" and "'ll" are left out.** "I'll check the price." is the preamble
  the model writes before a tool call. Two existing tests pin it as shown:
  - `test_rag09_output_check.py`, `test_a_preamble_before_a_tool_call_is_not_glued_to_the_answer`;
  - the gateway SSE test `test_the_gateway_stream_separates_two_model_calls_too`.
  Left out, no existing test changes. On W5 the item count is the same with or without them (21). The cost: a
  promise like RT-010's "and I'll check its current price" is kept. To include them instead, the user approves
  those two test changes by name, and every pre-tool preamble is dropped.
- **Decision 2 (advisor finding 2): what is left out of the user's wording.**
  - "tell you", "get you", "find", "pull up", "Let me check", "Happy to look up", "I'd";
  - "pricing", "cost(s)", "available";
  - a noun more than 26 characters after the verb.
  For example, "Want me to look up what the Halvardine Home Wren Bath Towel costs today?" is kept. Widening any of
  these is the user's call, and I would add each with a test.
- **"Fail-closed" means:** from the first trigger, the sentence is held until the check has decided. It is never
  released while undecided, and if the stream ends or errors, a held sentence is not sent (the existing
  `finish`/`abort` path). The fixed forms and the 26-character window are a narrow match by design, not a
  fallback: a sentence outside them is not an offer under the user's words.

**Mechanism** (`output_check.py`, a hard-rule 5 and 6 path; advisor finding 4):
- `offer` is a new class in `COUNTED`. It is not in `FIXED_SENTENCES` or `CLASSES`, so `_repeats` and the
  invariants test over `FIXED_SENTENCES` (`test_rag08_invariants.py`) do not see it. A separate
  `DROPPED_CLASSES = ("offer",)` names it.
- New triggers: `look`, `give`, `want`, `like`, `shall`, `should`. `check` is added too, because "I can check
  ..." already starts at the trigger `i `.
- Precedence, decided at the sentence's end: when `_advance` reaches the end of a sentence held for `offer`, it
  scans that sentence for every other class.
  - If one has a blocking match, meaning one that no exemption lets pass, that class's fixed sentence is shown and
    counted, as today. A live-backed price or stock value does not stop the drop.
  - Otherwise the sentence and the whitespace after it are dropped, and `counts["offer"]` goes up.
  - Text is never logged.
  So a sentence holding an unbacked price ("I can check the price: it's $45.") still gets the money sentence.
- `live_backed` is unchanged, because `offer` has no live exemption.
- Hard rule 11 (advisor finding 7): there is no exemption for the AI disclosure, because the user did not ask for one
  and it would fail open ("As an AI, I can look up the live price of X." would pass). Instead, a test holds that
  the disclosure survives when it stands in its own sentence, as the prompt writes it, and `tests/nfr08` replays.

### Addendum 8, update 3 (the user, 2026-11-23, under decision 0021): `ship` refuses before CI starts

**A real bug, owner #16.** DEV-1 removed the branch push trigger, so a PR's checks appear only after the PR
exists. `finish` then calls `ship` at once, and `gh pr checks --watch` returns immediately when no check exists
yet. The bucket read that follows sees a check still `pending` and refuses: "check python is pending", seen on
PR #48.

**Fix** in `tools/ship.sh`, which is control surface, listed in the PR body:
- **Wait for the checks to appear.** Before `--watch`, `check_jobs` polls `gh pr checks <pr> --json
  name,workflow` until every job in `REQUIRED_JOBS` has a check on the PR's head. If one is still missing at
  the deadline, it refuses with a message naming the missing jobs and saying that CI has not started on this
  PR's head.
- **A bounded wait.** The deadline is 600 s, polled every 15 s. `SHIP_CHECKS_WAIT` and `SHIP_CHECKS_POLL` must
  be digits. They can only shorten the wait: the wait is capped at 600 s, and the poll interval is at least 1 s
  and at most the wait. Any other value refuses. Shortening fails closed, because a short wait refuses sooner.
- **No other change.** After the wait, `--watch` and the bucket checks are unchanged.

**Tests** (`test-writer`, in `tests/ship/`):
- no checks on the first polls, then all appear: ship goes on to the watch and the merge;
- a required job never appears: it refuses at the deadline and names the job;
- a non-digit setting refuses;
- a setting above the cap is capped;
- the existing tests stay unchanged in substance.
  - The rig sets `SHIP_CHECKS_WAIT=0`, so a missing-job test refuses at once instead of waiting.
  - The fake `gh` gains a "no checks for the first N calls" switch.
  - No assertion is edited.

**Review:** in the same single `security-reviewer` pass as the offer rule and the proxy.
