## What this does

- **`services/mcp-catalog`, a new MCP server.**
  - It serves five read-only tools: `search_products`, `get_product`, `get_variant`, `check_stock` and `get_price`.
  - It runs over streamable HTTP on 127.0.0.1, behind the same per-turn token gate as mcp-rag.
  - The caller comes only from the token. The audience decides what the caller can see, and the region decides which price and stock it gets.
  - **Internal records (hard rule 7, RAG-11):**
    - A shopper sees only `public` products and variants.
    - An internal ID returns exactly the same `not_found` result as an ID that does not exist, in every region.
    - Search leaves internal products out.
    - P0009's canary, ID and title appear in no response.
  - **Live price and stock (hard rule 2):**
    - `get_price` and `check_stock` read an in-memory live store on every call. They never read the index.
    - The store is filled from the fixtures, and only after the fixtures pass the hash check.
    - The store can be changed with `set_price` and `set_stock`. These are not tools, so an MCP request cannot call them. This is the user's amended decision D2.
  - **Arguments (decision D3):**
    - Card data anywhere in the arguments is refused before any lookup or log.
    - An argument key the tool does not take is refused. (mcp-rag still ignores extra keys.)
    - Errors use the structured format, with fixed text.
  - **Scope (decision D1):**
    - `shopper-assistant` is now allowed the five tools, as PRD §7 lists.
    - They are not connected to the assistant yet: the assistant gets no catalog server address or token until #12.
- **L4: a token works only on the server it was made for.**
  - Each token now carries a signed `srv` claim.
  - `verify_for` checks the token and that claim together.
  - The token gate moved, unchanged in behaviour, to `northwind_common.mcp_gate`. It no longer uses Starlette and needs only the standard library. Each server's gate is bound to that server.
  - A token made for `northwind-rag` gets a bare 401 from mcp-catalog, and the reverse.
  - The gate reads the `authorization` header exactly as Starlette did; tests compare the two on missing, duplicate and mixed-case headers.
  - `mint` still defaults to `server="northwind-rag"`, because the one production caller is in `services/assistant` (off-limits this row). #12 removes the default.
- **Q4: `dataset_sha256` verified.**
  - `load_verified` / `verify_dataset` read every file the manifest lists, once each. They refuse symlinks and anything that is not a regular file, a FIFO included.
  - They recompute the dataset hash and raise on any mismatch.
  - Ingest checks first and stores the hash it verified.
  - mcp-catalog fills its store from the verified bytes.
  - mcp-rag's manifest reports `dataset_verified: true` only when the stored hash equals the hash of the fixtures on disk now (decision D4; no migration, no re-ingest).
  - This checks that the files match their manifest. It does not prove who wrote the manifest; CI's generator test is what catches a re-signed one.
- **`holds_card_data`** moved to `northwind_common.cards`, unchanged.
