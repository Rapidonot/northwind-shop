## What this does
- **`northwind_backend/inventory/`, deterministic code with no model call** (`$0`):
  - **`PostgresInventory`:**
    - stock rows are locked in one sorted order (`ORDER BY variant_id, node FOR UPDATE`), so concurrent orders
      can't deadlock;
    - units are taken by a conditional `UPDATE … WHERE on_hand - held >= q`, all or nothing per order;
    - `CHECK (0 <= held <= on_hand)` is the database's last guard;
    - the idempotency key is the reservation's primary key (`ON CONFLICT DO NOTHING`);
    - each transaction has `SET LOCAL` lock and statement timeouts.
  - **`InventoryFake`:** the same contract in memory, for unit tests and the replay harness.
  - **Holds:** a hold lasts 15 minutes (`HOLD`) on an injected clock, never the wall clock or `now()` in SQL. An
    expired hold never counts against stock on any read.
    - `commit` moves a live hold out of on-hand stock. An expired one is taken again only if its units are still
      free, otherwise `hold_expired`.
    - `release` is idempotent.
  - **Node choice:** the region's nodes from `regions.json`. For US, the postal prefix (after `US-`) decides:
    0–4 is DC-EAST first, 5–9 is DC-WEST first.
    - One node that fills the whole order wins; otherwise each line goes to the first node that can fill it.
    - A line is never split across nodes.
  - **Substitutes:** built by code with no model call. A candidate has:
    - the same department and subcategory;
    - public visibility (hard rule 7);
    - a live price within ±20% (hard rule 2);
    - enough stock at a single node.

    They are ranked in a fixed order, at most 3 and one per product, as IDs and a reason code only: no price and
    no count.
- **Wired into placement as code only** (`agents/orders_place.py`): no new tool, and no prompt, description or
  schema change.
  - Reserve after the payment claim and before the first authorization. A refusal escalates by code as
    `out_of_stock`, and a same-key hold that is no longer live escalates without authorizing.
  - Commit just before capture, so money is never captured for stock the order no longer holds.
  - Release when an escalation succeeds.
  - All of it goes through `AuditedInventoryPort` (`INVENTORY_PLACE = {reserve, commit, release}`). The audit
    records the key, order, region, line count and `dry_run`, never the postal code.
  - The escalation context reports the hold (`stock`, with `restock_needed`). It never reaches the model.
- **Data (option B, the user):** `generate._fit_to_stock` reserves and commits every order that reaches payment,
  in file order, through the fake. `BACKEND_DATA_VERSION` is 3.
  - Exactly two orders changed: O000476 (a quantity, 3 to 2) and O000936 (P0047-SND-REG-L to P0001-BLK-REG-L).
  - Tracking and labels are byte-identical.
- **M12:** a quantity below 1 (or over `MAX_QUANTITY`), a variant on two lines, or more than `MAX_LINES` lines is
  issue `invalid_line`. The order escalates with reason `invalid_line` and its own recommended action.
- **Dependency:** `psycopg[binary]` for `northwind-backend`. It was already locked, so `uv.lock` gains no new
  package (96 before and after).
