### 3.2 A named fixture: `evals/fixtures/a2a-05-partner/answers/<name>.json`

Each fixture holds:
- `name`, `kind`, `a2a05_use`, `message`, `region`;
- `script_sha256` and `message_sha256`;
- `assistant_id` (`northwind_evals.answerers.assistant_id`: the model, the prompt's sha8 and the check's sha8);
- `suite: "a2a-05-partner"`, `provisional: true`, `recorded` (the date);
- `context`: the first search's chunks (`chunk_id`, `source_id`, `source_type`, `text`);
- `refinements`: `n`, `query` and `chunks` for each `retrieve_context` call the model made;
- `answer`: `shown`, `sent`, `citations`, `resets`, `outcome` (`answered` or the fixed turn-cap reply);
- `upstream_calls`: the count, the model per call, and `stop_reason`;
- `disclosure`: `in_model_text` (the model's own text, from the cassettes, before the check) and `in_shown`, from (c).

Chunk text comes from the index, which holds no exact prices or stock (RAG-09).

### 3.3 The recorder: `evals/tests/test_a2a05_partner.py::test_partner_turn[<name>]`

The recorder carries three markers: `@pytest.mark.e2e`, `@pytest.mark.llm_suite("a2a-05-partner")` and
`parametrize` over the script. It uses the `llm_proxy` fixture, so all spending goes through `make record
SUITE=a2a-05-partner` in your window. It reuses `SavedFirstIndex` (from `northwind_evals.answerers`, imported and
not edited) and `serve_retriever`. It calls `stream_answer` directly, so it keeps the `Citations` event, which
`AssistantAnswerer` drops.

**Record mode:**
1. The first search runs on the live index (`CallerIndex` with `CachedEmbedder(FastEmbedEmbedder())`; a new
   query embeds live).
2. The same leak guard the eval CLI uses runs over those chunks: `contexts.leaks`, `internal_sources` and
   `load_canaries(required=True)`. It is rebuilt from public functions, because `cli._chunk_guard` is private.
   A leak fails the turn, and nothing is written.
3. The guard also runs inside the index on every refinement.
4. After the turn, the recorder checks the proxy's calls. It **fails on the first unexpected upstream request**:
   any model other than `ASSISTANT_MODEL`, more than `MAX_TURNS` (4) calls in one turn, a refusal, a fallback
   beta, or an error result.
5. The fixture is written only after every §4 check passes on it. With `PYTEST_ADDOPTS=-x`, the run stops
   there.

**Replay mode:** the recorder serves the fixture's saved context and refinements, with no DB and no embedder.
It re-runs `stream_answer` against the cassettes and asserts that `shown`, `sent` and `citations` equal the
fixture.

Because it is `e2e`, it runs in `make e2e` and CI's `e2e` job. **Change 2:** in replay it runs only while the
fixture's `assistant_id` equals the current `assistant_id()`. Otherwise it skips as stale, so a later row that
changes the prompt or the check (#12, #16, #17) is not forced to re-record. RECORD-ALL re-records it. The
recorder also checks the index manifest read-only before the first live search (change 1).

**Placement:** nothing goes in `evals/src/`, so the change adds no control surface there and nothing to
runner-sync. The one test file holds the script loader, the loader by name (`partner_fixture`) and the
recorder. A2A-05 (Window B) moves the loader into the A2A server package when it needs it.
