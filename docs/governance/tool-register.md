# Tool register (NFR-09)

Every tool and state-changing command, today and planned, with its risk tier, limit, approver and where
that is enforced. PRD §8 NFR-09 requires monetary tools to have a deterministic limit and a confirmation
or approval.

**Baseline:** main at `6f920a1`, 2026-11-06, with 5b and #7 landed. Updated 2026-11-07, at `7d45a40`, for the lines AUTO-2 names and nothing else. **Tiers:** `read-only`, `reversible write`, `irreversible or
monetary`. "The user" is the person at their own terminal. A session cannot push, use `gh` or run Docker
(decision 0004).

**Product agents hold ten tools today:** the assistant's `retrieve_context`, served by `mcp-rag` since #10;
since #20, the Orders subagent's two in-process reads, `get_fraud_assessments` and `get_payment_status`; and, since
#21, its seven placement tools on the fakes. Only those seven reach a payment or order write, and only through the
payment port's confirmation reference and per-order limit (decision 0014). No product agent can reach a refund or
a void. Claude Code sessions are different: a session can run `make record`,
`make eval-live` and `make enrich`, `make llm-proxy` too, and any sandboxed command can claim a window the
user opened (decision 0005, "Limits"). The file tools can reach both Edit rows at a prompt, and a sandboxed
`git commit` changed the committed baseline in rig run 2 (decision 0006, "Open limits"); since 5b, `Guard` and
`ship` refuse such a PR without its label, and both have run on GitHub, stated by the user, 2026-11-07 (`PROGRESS.md` row 5b). So a monetary tier here does not mean a session cannot reach the
row. Read each row's Enforced column.
